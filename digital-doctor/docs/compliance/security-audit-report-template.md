## 1. 系统概述

### 1.1 系统简介

数字医生分身（Digital Doctor）是一套面向内分泌科的AI辅助糖尿病管理平台，提供以下核心能力：

- **患者端**：糖尿病风险评估、AI化验单解读、血糖记录与趋势分析、用药提醒、AI健康教练
- **医生端**：患者管理与筛选、多维度指标趋势查看、临床预警处理、患者分配、审计日志查看
- **管理端**：科室与医生管理、指南参数配置、备份恢复、监控看板、系统告警
- **集成能力**：FHIR标准数据交换、OCR化验单识别、HIS系统对接

系统采用B/S架构，后端基于Python/FastAPI，前端基于React/Ant Design，数据存储基于PostgreSQL，缓存/消息队列基于Redis。

### 1.4 数据流向

```
患者数据采集 → 前端加密传输(TLS) → API网关验证(JWT) → 业务逻辑处理
    ├── PHI数据 → 加密存储(Fernet) → PostgreSQL
    ├── LLM调用 → 数据脱敏(白名单过滤) → 外部LLM API
    ├── 通知推送 → 消息队列(Redis) → Celery Worker → 微信/SMS
    └── 备份归档 → pg_dump + gzip → 本地/S3存储(SHA-256校验)
```

### 5.2 具体防护实现

#### SQL注入防护
- 全部数据库操作使用SQLAlchemy ORM的`select()`/`execute()`参数绑定
- 不使用原始SQL拼接
- Pydantic模型对所有输入进行类型和范围校验

#### XSS防护
- 前端使用React内置XSS防护（JSX自动转义）
- API响应Content-Type正确设置（application/json）
- CSP（Content Security Policy）头配置

#### CSRF防护
- JWT令牌通过Authorization Header传递（非Cookie）
- CORS白名单限制允许的Origin
- 敏感操作（患者分配、科室管理）记录审计日志

#### 认证安全
- 密码使用bcrypt哈希（passlib），不可逆
- JWT令牌有效期30分钟，支持refresh_token续期
- 手机号哈希存储（SHA-256），不出现在日志中
- 微信登录使用OAuth 2.0标准流程
- 操作审计日志包含user_id、action、resource_type、resource_id、时间戳

## 6. 数据安全

### 6.1 PHI（受保护健康信息）加密方案

| 数据类别 | 加密方式 | 密钥管理 | 加密时机 |
|---------|---------|---------|---------|
| 患者姓名 | 哈希存储(SHA-256) | 应用层 | 入库前 |
| 手机号 | 哈希存储(SHA-256) | 应用层 | 入库前 |
| 身份证号 | 正则脱敏(掩码) | 应用层 | 展示/日志 |
| 临床数据 | Fernet对称加密(PHI_ENCRYPTION_KEY) | 环境变量 | 入库前 |
| 微信OpenID | 哈希存储 | 应用层 | 入库前 |
| LLM输入 | 白名单脱敏(sanitize_for_llm) | 应用层 | 发送LLM前 |

### 6.2 数据分类分级

详见 [数据分类分级文档](./data-classification-policy.md)。

| 级别 | 类别 | 示例数据 | 加密要求 |
|------|------|---------|---------|
| L4 | 患者身份信息 | 姓名、身份证号、手机号、住址 | 哈希+加密，禁止明文存储 |
| L3 | 临床数据 | 血糖值、HbA1c、诊断信息、用药记录 | 加密存储，传输加密 |
| L2 | 运营数据 | 科室信息、医生信息、通知记录 | 访问控制，传输加密 |
| L1 | 公开信息 | 指南参数、健康提示模板 | 访问控制 |

### 6.3 数据脱敏策略

| 场景 | 脱敏方法 | 示例 |
|------|---------|------|
| 患者姓名 | 哈希存储，展示用`***`掩码 | `张**` |
| 手机号 | 哈希存储，脱敏正则替换 | `PHONE***` |
| 身份证号 | 正则脱敏替换 | `ID***` |
| 地址信息 | 关键词匹配+掩码替换 | `地址***` |
| LLM输入 | 白名单过滤（仅允许临床指标字段） | SAFE_CLINICAL_FIELDS |
| 审计日志 | 不记录敏感字段原文 | 仅记录user_id/action/timestamp |
| 日志输出 | 结构化日志自动排除name/phone/id_card字段 | - |
