## 1. 总则

### 1.1 目的

为规范数字医生分身系统中各类数据的分类、分级、存储、传输、使用和销毁的全生命周期管理，保障患者隐私和医疗数据安全，依据《中华人民共和国数据安全法》《中华人民共和国个人信息保护法》《健康医疗大数据标准、安全和服务管理办法》及相关法规制定本规定。

### 1.2 适用范围

本规定适用于数字医生分身系统在生产、测试、开发环境中涉及的全部数据资产。

### 1.3 数据分类原则

- **最小够用原则**：仅采集和处理业务必需的最少数据
- **分级管控原则**：不同级别数据采用不同安全措施
- **生命周期原则**：覆盖数据从采集到销毁的全过程
- **责任明确原则**：每类数据有明确的责任部门和责任人

## 2. 数据分类体系

### 2.1 分类维度

| 维度 | 说明 | 分类值 |
|------|------|--------|
| 数据主体 | 数据关联的主体对象 | 患者、医生、机构、系统 |
| 数据性质 | 数据的业务性质 | 身份信息、临床数据、运营数据、公开信息 |
| 数据来源 | 数据的产生来源 | 用户输入、设备采集、系统生成、第三方接入 |

### 2.2 数据类别定义

| 类别 | 范畴 | 数据项举例 |
|------|------|-----------|
| 患者身份信息 | 可识别自然人身份的信息 | 姓名、身份证号、手机号、住址、出生日期 |
| 患者临床数据 | 诊疗过程中产生的健康医疗数据 | 血糖值、HbA1c、诊断信息、用药记录、化验报告 |
| 医生/员工信息 | 医务人员的工作身份信息 | 姓名、工号、执业证号、科室、职称 |
| 机构运营数据 | 医院管理相关的运营数据 | 科室设置、排班信息、通知记录、审计日志 |
| 系统配置数据 | 系统运行所需的配置参数 | 指南参数、通知模板、备份策略 |
| 公开信息 | 可对外公开的非敏感信息 | 健康知识库、产品说明、使用指南 |

## 3. 数据分级标准

### 3.1 级别定义

| 级别 | 名称 | 定义 | 泄露影响 |
|------|------|------|---------|
| **L4** | 最高敏感级 | 可直接识别患者个人身份的核心标识信息 | 严重侵犯隐私，可能造成身份盗用、诈骗 |
| **L3** | 高度敏感级 | 患者临床诊疗数据和医生执业信息 | 侵犯患者隐私，可能影响诊疗安全 |
| **L2** | 中度敏感级 | 机构运营数据和系统配置数据 | 可能影响系统正常运行或管理秩序 |
| **L1** | 低度敏感级 | 可公开的非敏感信息 | 基本无影响 |

### 3.2 分级对照表

| 级别 | 数据项 | 示例 | 分类依据 |
|------|-------|------|---------|
| L4 | 患者姓名(明文) | `张三` | 直接标识符 |
| L4 | 身份证号 | `310xxx19900101xxxx` | 唯一身份标识 |
| L4 | 手机号 | `138xxxx1234` | 直接联系方式 |
| L4 | 家庭住址 | `XX省XX市XX路XX号` | 个人位置信息 |
| L4 | 微信OpenID | `oABCDxxxx` | 可关联微信账号 |
| L4 | 面部图像(原始) | 化验单照片 | 生物特征 |

| L3 | HbA1c | `HbA1c: 7.5%` | 临床健康数据 |

| L1 | 健康提示模板 | 每日健康提示 | 公开模板 |

## 4. 各级数据存储要求

### 4.1 L4 — 最高敏感级

| 要求项 | 具体措施 | 实施方式 |
|-------|---------|---------|
| 加密算法 | AES-256 或 Fernet (AES-128-CBC + HMAC-SHA256) | `encrypt_phi()` |
| 加密粒度 | 字段级加密 | 每条PHI字段独立加密 |
| 密钥管理 | 环境变量注入，不写入代码/配置文件 | `PHI_ENCRYPTION_KEY` |
| 密钥轮换 | 建议180天轮换一次 | 运维流程 |
| 哈希存储 | 非对称场景使用SHA-256哈希(HMAC) | 手机号查询匹配场景 |
| 备份加密 | 备份文件启用存储加密 | `BACKUP_ENCRYPTION_ENABLED=true` |
| 访问日志 | 所有访问记录审计日志 | `operation_audit` |
| 脱敏展示 | 前端展示仅显示掩码 | `张**` / `138****1234` |

### 4.2 L3 — 高度敏感级

| 要求项 | 具体措施 | 实施方式 |
|-------|---------|---------|
| 加密算法 | AES-128或以上 | `encrypt_phi()` |
| 访问控制 | RBAC + 科室隔离 + 患者授权检查 | `require_patient_access()` |
| 审计记录 | 每次读取记录操作审计 | `operation_audit.log_operation()` |
| 展示控制 | 仅授权医生可查看完整数据 | 前端按角色展示 |
| LLM传输 | 白名单过滤脱敏后传输 | `sanitize_for_llm()` |

### 4.3 L2 — 中度敏感级

| 要求项 | 具体措施 |
|-------|---------|
| 访问控制 | 基于角色的访问控制（RBAC） |
| 传输加密 | TLS 1.2+ 加密传输 |
| 日志记录 | 变更操作记录审计日志 |
| 备份保护 | 纳入日常备份范围 |

### 4.4 L1 — 低度敏感级

| 要求项 | 具体措施 |
|-------|---------|
| 访问控制 | 基本的认证访问 |
| 完整性保护 | 防止未授权篡改 |
| 备份保护 | 纳入配置备份范围 |

## 6. 数据生命周期管理

### 6.1 采集阶段

```
患者信息采集:
  ├── 注册：手机号 → SHA-256哈希存储
  ├── 评估：年龄/BMI/腰围/家族史 → 明文存储(L3)，接口加密传输
  ├── 血糖：设备读数 → AES加密存储
  └── 化验单：OCR识别 → 原始图像存储(L4加密)，识别结果(L3加密)
```

| 控制点 | 要求 |
|-------|------|
| 采集告知 | 采集前展示隐私政策，获取明确同意 |
| 最小采集 | 仅采集业务必需的字段 |
| 实时校验 | Pydantic模型校验输入范围 |
| 即时加密 | L4/L3数据入库前即完成加密 |

### 6.2 存储阶段

| 控制点 | 要求 |
|-------|------|
| 加密存储 | L4/L3数据字段级加密 |
| 访问控制 | 数据库仅允许应用层访问（非直连） |
| 冗余保护 | 主从复制 + 定期备份 |
| 备份保护 | pg_dump + SHA-256校验 |
| 存储周期 | 临床数据最低保存15年（电子病历规范） |

### 6.3 使用阶段

| 控制点 | 要求 |
|-------|------|
| 身份认证 | JWT令牌校验，30分钟过期 |
| 权限校验 | 基于RBAC + 科室隔离 + 患者授权 |
| 审计记录 | 所有访问写入operation_audit |
| 脱敏展示 | 前端展示掩码化 |
| LLM使用 | 白名单过滤79个安全字段 |
| 导出控制 | 数据导出需审批 |

### 6.4 归档阶段

| 控制点 | 要求 |
|-------|------|
| 归档条件 | 患者账号注销或超过活跃期限 |
| 归档格式 | 加密压缩，保留元数据 |
| 归档保管 | 异地备份，S3/MinIO冷存储 |
| 恢复流程 | 需管理员审批+操作审计 |

### 6.5 销毁阶段

| 控制点 | 要求 |
|-------|------|
| 销毁条件 | 超过法定保存期限或用户请求删除 |
| 销毁方式 | 数据库记录物理删除，备份文件安全擦除 |
| 销毁确认 | 记录销毁审计日志 |
| 备份同步 | 确认所有备份副本均已销毁 |
| 不可恢复 | 确保删除后不可通过技术手段恢复 |

## 10. 附录

### A. 术语定义

| 术语 | 定义 |
|------|------|
| PHI (Protected Health Information) | 受保护健康信息，包括个人身份信息和健康数据 |
| 脱敏 (De-identification) | 移除或模糊化可识别个人身份的数据处理过程 |
| 白名单过滤 | 仅允许预定义的字段通过，其余全部拒绝 |
| RBAC (Role-Based Access Control) | 基于角色的访问控制 |
