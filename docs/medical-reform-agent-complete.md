# 第一部分：系统架构

## 1.1 系统定位与核心价值

### 目标用户
- **一级用户**：县领导（县委书记/县长）、卫健委主任
- **二级用户**：医共体牵头医院院长、医保局局长、疾控中心主任
- **三级用户**：乡镇卫生院院长、村医代表

### 核心价值主张
以"最小数据输入"换取"最大决策支撑"——用户仅需提供本地基础卫生统计数据，智能体即可自动对标全国/全省最佳实践，发现关键问题，生成可落地的医改方案。

### 设计原则

| 原则 | 说明 |
|------|------|
| 证据驱动 | 每个建议必须有数据支撑和案例参照 |
| 因地制宜 | 根据当地经济水平、人口结构、地理特征推荐差异化方案 |
| 渐进可行 | 区分"紧急必做""短期优化""中长期建设"三层优先级 |
| 闭环验证 | 内置PDCA跟踪机制，方案可执行、可监测、可迭代 |

## 1.3 部署方式

| 方式 | 适用场景 | 优势 | 劣势 |
|------|---------|------|------|
| SaaS云端 | 信息化基础薄弱的县 | 零运维、快速上线 | 数据上云顾虑 |
| 私有化部署 | 对数据安全敏感的县 | 数据不外传 | 需要运维能力 |
| 混合模式 | 兼顾安全与便捷 | 敏感数据本地、知识库云端 | 架构复杂度高 |

数据安全底线：患者个体数据不可上传，仅需汇总统计数据；所有传输加密（TLS 1.3）；私有化部署支持完全离线运行。

# 第二部分：主控智能体（Controller Agent）

## 2.1 角色定义

**类比角色**：类似三甲医院的"医务部主任"——不亲自做手术（不做具体分析），但决定请哪些科室会诊（调度哪些专业Agent）、按什么顺序（工作流编排）、最终方案是否达标（质量审核）。

## 2.2 意图识别与任务分类

```
输入："我们县这两年住院费用涨得很快，不知道问题出在哪"
  ↓
意图解析：
  - 主意图：费用异常诊断（置信度 0.92）
  - 次意图：费用控制方案推荐（置信度 0.78）
  - 隐含意图：是否与医保支付方式有关？是否与医共体建设不足有关？
  ↓
任务分解：
  1. [数据诊断Agent] 分析住院费用增长趋势、结构、区域对比
  2. [三医联动Agent] 分析费用增长与医保支付方式、药品耗材价格的关系
  3. [案例匹配Agent] 检索"住院费用控制"主题下的标杆做法
  4. [方案生成Agent] 综合前三步输出，生成费用控制方案
  ↓
流程编排：1→2→3→4，其中1和3可并行执行
```

意图分类器采用两级路由：
- **一级分类**（5大类）：全面诊断 / 专题分析 / 方案生成 / 进度跟踪 / 应急预警
- **二级分类**（15个子类）：费用专题 / 医共体专题 / 医保专题 / 医防融合专题 / 信息化专题等

## 2.4 质量审核Gate

每个Agent输出后自动执行质量检查：
1. **完整性检查**：必填字段是否齐全
2. **一致性检查**：当前Agent输出是否与前置Agent输出矛盾
3. **置信度检查**：置信度<0.7 → 标记需人工确认
4. **合规检查**：建议是否符合国家政策方向

不通过则执行重试-修正循环（最多3次）。

## 2.5 冲突仲裁机制

当并行Agent产生矛盾结论时：
1. 提取矛盾点
2. 回溯输入数据是否一致
3. 检查知识库版本是否相同
4. 若数据一致但结论矛盾 → 标记"需人工判断"并附双方推理链
5. 若数据不一致 → 以数据诊断Agent输出为准，通知另一方重新计算

# 第三部分：11个专业智能体深度设计

## Agent 1：数据诊断智能体（Data Diagnostic Agent）

### 角色定义
**类比角色**：体检中心总检医师——不是只看一个指标，而是把所有指标放在一起看，找出异常模式。掌握全国2188个县的统计数据分布，知道什么叫"正常"、什么叫"偏离"。

### 输入数据规范

**必需输入（12项最小数据集 MVDS）**：

| 编号 | 数据项 | 计算口径 | 对标指标 |
|------|--------|---------|---------|
| D01 | 常住人口数（万人） | 统计年鉴口径 | 分母基准 |
| D02 | 65岁以上人口占比（%） | 统计年鉴口径 | 老龄化校正 |
| D03 | 基层诊疗人次占比（%） | 基层诊疗量/县域总诊疗量 | 指标7 |
| D04 | 县域内住院人次占比（%） | 县域内住院/参保人总住院 | 指标11 |
| D05 | 县域内住院次均费用（元） | 住院总费用/住院人次 | 指标10 |
| D06 | 县域内门诊次均费用（元） | 门诊总费用/门诊人次 | 补充 |
| D07 | 医保基金县域内支出占比（%） | 县域内医保支出/总支出 | 指标8 |
| D08 | 医保基金基层支出占比（%） | 基层医保支出/县域内总支出 | 指标9 |
| D09 | 中级以上医师下沉人数/万常住人口 | 下沉人数/万常住人口 | 指标4 |
| D10 | 基层与牵头医院人均收入比值 | 基层人均收入/牵头医院人均收入 | 指标6 |
| D11 | 慢病规范管理率（%） | 规范管理人数/患病人数 | 指标13 |
| D12 | 四类慢病过早死亡率（/10万） | 标准化死亡率 | 指标14 |

**输入校验规则**：
- 占比类数据须在0-100之间，费用类须>0
- 与上年数据波动>30% → 标记警告但接受
- 缺少D01-D04任一项 → 拒绝，提示最少数据需求

### 核心推理逻辑

**阶段一：单指标对标**

```
FOR each indicator:
    Z-score = (实际值 - 参照均值) / 参照标准差
    百分位 = 正态分布累积概率(Z-score)
    
    IF 百分位 >= 80: 绿色（优秀）
    ELIF 百分位 >= 50: 浅绿（良好）
    ELIF 百分位 >= 30: 黄色（需关注）
    ELIF 百分位 >= 10: 橙色（明显落后）
    ELSE: 红色（严重落后）
```

**阶段二：交叉指标异常模式识别**

维护一个模式库（Pattern Library），持续扩充：

| 模式 | 触发条件 | 解释 | 建议方向 |
|------|---------|------|---------|
| 基层空心化 | 基层诊疗占比↓ + 县级诊疗量↑ + 下沉医师↓ | 基层服务能力退化 | 强化基层建设、调整医保差别化支付 |
| 费用驱动型外流 | 住院次均费用↑ + 县域住院占比↓ + 县域医保支出↓ | 县域费用高致患者外流 | 控制费用、提升大病救治能力 |
| 只管不控 | 慢病管理率↑ + 慢病住院率↑ | 慢病管理流于形式 | 强化管理质量、引入按人头付费 |
| 投入产出倒挂 | 卫技人员↑ + 设备↑ + 基层诊疗占比↓ | 资源投入未转化为产出 | 核查资源使用效率 |
| 医保资金外溢 | 县域外医保支出↑ + 县域就诊率↓ | 患者和资金双外流 | 急建核心专科、建立转诊审核机制 |
| 上下收入失衡 | 牵头医院收入↑ + 基层收入停滞 + 基层空编率↑ | 薪酬差距致人才流失 | 调整绩效分配 |

**阶段三：县域医疗健康综合画像**

生成5维度雷达图（对标国卫办基层发〔2024〕22号14项指标）：
- 紧密型（定性3项）：20%
- 同质化（定量3项）：20%
- 促分工（定量3项）：20%
- 提效能（定量3项）：20%
- 保健康（定量2项）：20%

### 输出规范（核心字段）

```json
{
  "diagnosis_summary": {
    "overall_score": 72.5, "overall_grade": "良好",
    "national_percentile": 55, "provincial_percentile": 48,
    "key_findings": [
      {"severity": "red", "indicator": "基层诊疗占比", "value": 42.3, "benchmark": 58.6, "gap": -16.3}
    ]
  },
  "radar_scores": {"紧密型": 68, "同质化": 55, "促分工": 62, "提效能": 78, "保健康": 85},
  "anomaly_patterns": [

  ],
  "confidence": 0.85
}
```

### 知识库依赖
- 监测指标库：14项指标计算公式、阈值、参考范围。对标基准：国卫办基层发〔2020〕12号（26项，试行）→ 国卫办基层发〔2024〕22号（14项，现行标准）
- 全国统计数据：2188个县的指标分布（均值、标准差、五分位数）

## Agent 2：三医联动分析智能体（Tripartite Reform Agent）

### 角色定义
**类比角色**：三栖顾问——同时精通医院财务、医保精算和药品采购。核心能力是理解三者的**传导机制**。

### 核心推理逻辑

**阶段一：医疗端结构分析（对标三明基准）**

```
理想结构（参照三明2023年实际）：
  医疗服务收入占比：48.75%
  药品收入占比：<25%
  耗材收入占比：<15%
  检查化验收入占比：<20%

偏离度诊断：
  IF 药品占比 > 30%: 标记"药品依赖" — 可能存在以药养医
  IF 耗材占比 > 20%: 标记"耗材依赖" — 可能存在高值耗材滥用
  IF 医疗服务占比 < 35%: 标记"技术价值低估"
  IF 检查化验占比 > 25%: 标记"设备驱动" — 可能存在过度检查
```

**阶段二：医保端可持续性分析**

```
当年结余率 = (当年收入 - 当年支出) / 当年收入
累计结余可支付月数 = 累计结余 / (当年支出/12)

预警阈值：
  累计结余可支付月数 < 3: 红色（穿底风险）
  3-6: 黄色 / 6-9: 浅绿 / >9: 绿色
```

**打包支付模拟模型**（核心差异化能力）：

```
模拟场景："如果按照三明模式将医保基金打包给医共体"
输入：当前县域内医保总支出 / 县外支出 / 预计可减少的转诊比例 / 预计可降低的住院率
输出：打包预算总额 / 预计结余金额 / 财务平衡点
参照：三明2020年包干26.21亿元结余4.9亿元；2026年三部门14条"结余不作为次年调减因素"
```

**阶段三：三医传导矩阵**

分析任意环节变化如何传导到另外两个环节。例如：
- 医疗服务价格上调10% → 医保短期支出增加约3%，但2年内通过减少药品支出对冲 → 药占比预计下降3-5个百分点
- 推行按病种付费 → 住院次均费用下降预估X% → 集采品种使用率提升
- 扩大集采范围 → 药品费用下降 → 医保释放空间可用于提高医疗服务价格

### 知识库依赖
- 三明12年完整参照：12轮价格调整（1.04万项次）、C-DRG结算占比从0%→81.58%、医生均薪从5.65万→19.56万
- 医保支付改革库：DRG/DIP覆盖率从2021年启动到2025年95%覆盖的完整时间线
- 三部门2026年14条：门诊按人头付费+慢病管理结合、结余不作为次年调减因素

## Agent 3：医共体评估智能体（Medical Community Assessment Agent）

### 角色定义
**类比角色**：组织架构咨询顾问 + 医院管理评审员。不只看"有没有"成立医共体（形式），而是评估"紧不紧"（实质）和"好不好"（效果）。

### 核心推理逻辑：四大共同体成熟度评估

**利益共同体评估**（核心问题：是不是一条船上的）
- 医保支付纽带：全额打包100分 → 部分打包70分 → 按项目付费0分
- 薪酬分配纽带：全员年薪制100分 → 绩效统一分配70分 → 独立分配30分
- 发展投入纽带：政府六项投入全额保障（三明模式）100分 → 部分保障60分 → 自主发展20分

**服务共同体评估**（核心问题：患者能否有序流动）
- 分级诊疗实现度：基层诊疗占比/目标值 × 权重 + 下转增长率 × 权重
- 同质化能力：六大共享中心覆盖率 + 基层能开展病种数/国家推荐基层病种数
- 连续性服务："防筛诊治管康"六环节每个有专门制度=1分，满分6分

**管理共同体评估**（核心问题：是否真正统一管理）
- 人事统一度（统一招聘/培训/调配/考核）、财务统一度（统一核算/统收统支/统一预算）
- 药械统一度（统一用药目录/采购配送/支付货款）、信息统一度（互联互通等级）

**责任共同体评估**（核心问题：结果好不好、谁对结果负责）
- 健康结果责任、费用责任、满意度责任

### 五级成熟度分级

| 等级 | 名称 | 总分范围 | 典型特征 |
|------|------|---------|---------|
| L1 | 起步型 | <40 | 刚挂牌，人财物未统一 |
| L2 | 成长型 | 40-59 | 部分统一（如仅药品统一），共享中心在建 |
| L3 | 成熟型 | 60-79 | 人财物基本统一，医保部分打包 |
| L4 | 示范型 | 80-89 | 全面统一+医保全打包+效果持续改善 |
| L5 | 卓越型 | ≥90 | 四大共同体均高水平运行，可对外输出经验 |

### 知识库依赖
- 组织架构模式库：南宁两种法人治理模式（独立法人总医院 vs 保留法人统一管理）、各地"六统一"/"八统一"实践
- 标杆参照：濉溪（2024双第一）、准格尔旗（2025国家级典型，就诊率89.88%）、余庆（三兜底政策）、蓝山（DIP兼容改革）

## Agent 4：医防融合规划智能体（Medical-Prevention Integration Agent）

### 角色定义
**类比角色**：公共卫生专家 + 慢病管理顾问。核心问题：如何把"治病赚钱"的激励，扭转为"防病省钱"的激励。

### 核心推理逻辑

**阶段一："防筛诊治管康"全链条完整度评估**

对"三高六病"（高血压、高血糖、高血脂 + 冠心病、脑血管病、慢性肾病、慢阻肺、糖尿病、癌症）逐一评估六环节：
- 每个环节评分：0=缺失 / 1=有制度未执行 / 2=部分执行 / 3=规范执行
- 全链条得分 = SUM(各环节得分) / (6病种 × 6环节 × 3分) × 100

**阶段二：疾控融入医共体程度评估（对标新疆"健共体"模式，2025.12）**
- 组织融入（20+10+15分）：公卫管理中心/疾控兼任/临床嵌入
- 信息融入（15+15+10分）：传染病报告/HIS互通/死因监测
- 绩效融入（15+10分）：公卫考核关联/临床指标纳入
- 满分100分

**阶段三：慢病按人头付费模拟（对标湾沚区"红黄绿"三色管理）**

```
输入：某慢病患者人群 / 当前人均费用 / 当前住院率 / 目标住院率
计算：人头费标准 = 当前人均费 × (1 - 效率提升率) + 公卫经费慢病部分
分级：绿标（稳定期，季度随访） / 黄标（波动期，月度随访） / 红标（急性期，加强管理）
激励：结余按70%奖励管理团队，超支按50%共担
```

## Agent 6：绩效考核监测智能体（Performance Monitoring Agent）

### 角色定义
**类比角色**：医改成效的"仪表盘"——自己不造车（不做改革），但持续监控车速、油量、发动机温度，一旦异常立即报警。

### 核心推理逻辑

**阶段一：逐指标状态机追踪**

```
GREEN → (连续2季度不达标) → YELLOW
YELLOW → (连续2季度达标) → GREEN
YELLOW → (连续2季度不达标) → RED
RED → (连续2季度达标) → YELLOW
RED → (连续4季度不达标+无改善趋势) → BLACK（需紧急干预）
```

**阶段二：归因分析（根因追溯树）**

当指标触发预警时，自动遍历根因树：
- 供给端：基层医师减少？→查指标4 / 设备故障？→查共享中心数据 / 药品缺货？→查药房数据
- 需求端：县级吸引力增强？→查县级门诊量 / 季节性因素？→查去年同期
- 制度端：医保支付调整？→查医保政策 / 用药目录限制？→查药品目录 / 绩效方案？→查考核变化
- 数据端：统计口径变化？→查采集方式 / 上报延迟？→查完整率

**阶段三：趋势分析**

使用移动平均趋势线+季节性分解+目标差距推算+标杆追赶模拟

**阶段四：综合绩效评分**

综合得分 = Σ(各指标得分 × 指标权重)。指标得分逻辑：实际值≥目标值满分，≥目标90%得90%分，以此类推。改善额外+5%奖励，恶化额外-10%惩罚。

权重参照国家监测体系：紧密型27分/同质化27分/促分工18分/提效能18分/保健康10分

## Agent 10：风险预警智能体（Risk Alert Agent）

### 角色定义
**类比角色**：医改路上的"风险雷达"——提前识别各类风险并评估其概率和影响。

### 14项风险分类与识别规则

**第一类：财务风险**
- R01 医保基金穿底风险：累计结余可支付月数<3 → 最高级别预警
- R02 医院债务风险：资产负债率>60%或流动比率<1.0
- R03 改革投入不足风险：信息化预算<最低标准且无明确来源

**第二类：人才风险**
- R04 基层人才流失：空编率>20%或年离职率>10%
- R05 关键岗位断层：牵头医院骨干50岁以上占比>60%
- R06 执行人才缺乏：医共体管理中心专职<5人

**第三类：执行风险**
- R07 推进缓慢：超2个里程碑延迟>30天
- R08 部门协调障碍：卫健/医保/财政联合发文<2件/年
- R09 数据质量风险：关键指标完整性/一致性<90%

**第四类：舆情风险**
- R10 群众满意度下降>5个百分点
- R11 医务人员抵触（年薪制/绩效改革受阻>3个月）
- R12 媒体负面报道

**第五类：外部风险**
- R13 政策变化风险（低概率高影响）
- R14 突发公卫事件冲击（低概率高影响）

### 风险评估矩阵（概率×影响）

```
影响 ↑
高  │ R13 R14(监控)    R01(重点防范)    R01/R02恶化(立即响应)
中  │ R05 R06 R09(常规) R03 R07 R08(预案) R04 R10(重点防范)
低  │ R12(低优先级)    R11(常规关注)    R02初现(预案)
    └──────────────────────────────────────→ 概率
       低(<20%)         中(20-50%)        高(>50%)
```

```
链1：人才流失连锁 → R04→基层能力↓→诊疗占比↓→患者涌向县级→超负荷→外流→R01
链2：改革执行陷阱 → R07→错过窗口→无法获补→R03→改革停滞→转为形式主义
```

# 第五部分：Prompt工程与上下文管理

## 5.1 各Agent Prompt策略概要

| Agent | Prompt核心策略 |
|-------|--------------|
| 数据诊断 | 不要孤立看指标，找异常关联模式。每个发现给：数据证据+偏离程度+可能原因(≤3个)+置信度 |
| 三医联动 | 同时精通医院财务、医保精算、药品采购。分析任何维度时同时评估对另外二维的传导影响 |
| 医共体评估 | 评估不等于打分——找得分低背后的根因。每个扣分点有：原因+证据+改进建议 |
| 医防融合 | 慢病管理不看"管理率"看"控制率"和"住院率"——三者关系告诉你管理质量 |
| 信息化规划 | 不推销产品。从业务问题反推信息化需求，从现有系统出发规划升级路径。必须三档方案+真实中标价 |
| 绩效考核 | 异常指标必须追溯根因(≥2-3个候选原因，按数据证据排序)。趋势比绝对值重要 |
| 案例匹配 | 找最像的案例不仅看经济水平，还要看人口、地理、改革阶段。每个做法标注可复制性+证据等级 |
| 方案生成 | 方案逻辑主线≤3个核心问题。每个对策有根因→措施→标杆→效果链条。不空谈"加强""完善" |
| 费用估算 | 数字必须有来源依据(哪个县、何时、什么规模、中标价)。不编造数字 |
| 风险预警 | 每个风险有：触发条件+概率+影响+预案。关注风险联动——一个触发引发连锁反应 |
| 政策合规 | 审查≠挑错——也主动识别政策红利。每个问题引用具体政策文号 |

## 5.2 分层上下文注入策略

```
L1 永久上下文（始终注入）：角色定义+输出规范+核心推理框架（~500 tokens）
L2 工作流上下文（任务期间注入）：任务定义+前置Agent关键输出摘要（~1000 tokens）
L3 知识检索结果（按需注入）：知识路由器返回片段+来源引用（~2000 tokens）
L4 历史会话上下文（PDCA任务注入）：上一周期诊断结果+关键变化（~1000 tokens）

设计目标：单次Agent调用上下文占用≤5000 tokens，留出充足的推理空间
```

## 6.6 参照数据的使用优先级

```
第一优先：同省同类县域最新数据（2024-2026）
第二优先：同经济水平同类县域最新数据（2024-2026）
第三优先：全国均值/全国标杆（2024-2026）
第四优先：三明同期数据（方向性参照）
第五优先：国际同类模式（方法论参照）
第六优先：2020-2023历史数据（趋势分析+基线对比）
```

**时效性标注规范**：
- [2026] = 当年最新，权威性最高
- [2024-2025] = 近2年，可作对标基准
- [2020-2023] = 历史基线，用于趋势分析，不作当前对标
- [国际] = 方法论参照，不作直接数据对标

## 6.7 知识库更新机制
