# "星原"AI稿件撰写智能体：功能与场景定位

## 〇、产品定义与核心价值

### 产品定位

"星原"AI稿件撰写智能体，聚焦政务、医院、党建三大高频发稿场景，以"专属训练、高效生成、合规可控、闭环迭代"为核心，打造贴合垂直行业需求的智能撰稿解决方案。区别于通用AI写作工具，主打"行业适配性+文风精准度+合规可控性"三维差异化，助力用户降低撰稿成本、提升出稿效率，同时严格把控内容规范与政治口径，成为政务、医疗、党建领域宣传岗、文案岗的核心辅助工具。

### 核心差异化

不追求"大而全"的通用写作能力，而是聚焦垂直领域做深做透：

| 对比维度 | 通用AI写作工具（ChatGPT、文心一言等） | 通用办公工具（OA排版、WPS校对） | "星原"AI稿件撰写智能体 |
|----------|--------------------------------------|-------------------------------|----------------------|
| 文风适配 | 通用化输出，文风随机，无法复刻单位特色 | 不涉及内容生成 | 基于RAG检索增强，精准复刻单位历史文风，一致性≥90% |
| 合规审核 | 无行业合规能力，政治术语易出错 | 格式合规，无内容审核 | 内置新华社禁用词库+政务/医疗/党建专属词库+用户自定义敏感词库，三重过滤 |
| 格式规范 | 不遵循公文格式标准 | 格式规范但需人工操作 | 自动对齐GB/T 9704-2012公文格式标准及行业规范，一键生成合规格式 |
| 持续学习 | 无记忆能力，每次从零开始 | 不涉及 | 定稿回流迭代，越用越精准 |
| 数据安全 | 数据上传公有云，有泄露风险 | 本地化但功能单一 | 支持私有化部署，数据不出内网 |
| 领域深度 | 泛化，无行业聚焦 | 无行业属性 | 专注政务/医院/党建三大场景，70+类专属模板 |

| 文心一言 / 通义千问 | 国内通用大模型 | 中文能力强、合规备案 | 无法做单位级风格复刻、无闭环迭代 | 单位级专属训练+定稿回流学习+权限管理 |

## 一、技术架构概述

"星原"AI稿件撰写智能体采用"基础模型+行业知识库+RAG检索增强+合规过滤层"四层技术架构，兼顾生成质量、响应速度与合规安全：

```
┌─────────────────────────────────────────────────────┐
│                    应用层                            │
│  稿件生成 │ 文风训练 │ 合规审核 │ 定稿回流 │ 权限管理  │
├─────────────────────────────────────────────────────┤
│                  合规过滤层                          │
│  禁用词过滤 │ 政治口径校验 │ 格式规范检查 │ 错别字校对 │
├─────────────────────────────────────────────────────┤
│                 RAG检索增强层                        │
│  向量检索(HyDE) │ 多路召回 │ Re-ranking │ 知识图谱   │
├─────────────────────────────────────────────────────┤
│                   知识库层                           │
│  素材库 │ 模板库 │ 禁用词库 │ 定稿库 │ 政策知识库     │
├─────────────────────────────────────────────────────┤
│                   模型层                             │
│  国产大模型基座 │ 领域SFT微调 │ RLHF对齐 │ 推理优化   │
└─────────────────────────────────────────────────────┘
```

### 关键技术选型

**1. 模型策略**
- **基座模型：** 选用国产合规大模型（如DeepSeek、通义千问等通过备案的模型），兼顾中文理解能力与合规要求
- **领域优化：** 针对政务、医院、党建三大领域进行SFT（监督微调），注入行业语料，提升领域术语准确率
- **对齐策略：** 采用RLHF（人类反馈强化学习）对齐策略，确保输出符合政治口径与行业规范；参考Anthropic Constitutional AI思路，内置"合规宪法规则"（如：坚持正确政治方向、不编造事实、不使用禁用词），在生成阶段即对齐，而非仅事后审核

**2. RAG检索增强策略**
- **文档解析：** 支持Word、PDF、TXT等格式的精确解析，智能识别公文格式元素（发文机关标识、发文字号、标题层级、版记等）
- **向量化（Embedding）：** 基于中文优化的Embedding模型，对素材进行向量化存储，支持语义检索
- **检索策略：** 采用HyDE（假设文档嵌入）+多路召回+Re-ranking策略，先根据用户输入生成"假设稿件"用于检索，再对召回结果进行相关性重排序，提升文风复刻精准度
- **知识图谱增强（Graph RAG）：** 参考Microsoft Graph RAG思路，将用户素材中的人物、事件、时间、机构等实体构建为知识图谱，检索时不仅匹配文本相似度，还能关联相关事件和人物关系，提升稿件信息深度和连贯性

**3. 幻觉控制机制**
- **Chain-of-Verification（验证链）：** 参考Meta AI思路，生成初稿后自动执行多步验证：事实核查→数据核对→人名/职位/时间等关键信息校验→输出可信度评分
- **RARR（溯源归因）：** 参考Google Research方法，对稿件中每个事实性陈述进行溯源，标注信息来源（引用自哪篇历史稿件/政策文件），增强稿件可信度
- **可信度标签：** 每篇生成稿件附带"可信度评分"（高/中/低），帮助审核人员快速判断需要重点审核的段落

**4. 持续学习机制**
- **定稿回流：** 用户审核修改后的定稿自动回流至知识库，更新用户专属Embedding，实现"越用越准"
- **模型版本管理：** 记录每次模型迭代的训练数据、参数变化和效果对比，支持版本回滚和效果对比
- **人机协同评分：** 参考Stanford HAI的Human-AI Scoring方法，每次人工修改量被记录为质量标签，累积用于模型优化

## 二、核心功能定位

核心功能围绕"素材学习—稿件生成—审核优化—迭代升级"全链路设计，深度适配政务、医院、党建稿件的文风要求、格式规范与口径标准，拒绝通用化输出，凸显行业专属属性，同时兼顾操作便捷性，让非专业撰稿人员也能快速上手。

### （一）专属文风训练功能（核心壁垒）

**功能目标：** 构建用户单位专属的"文风模型"，让AI写出"像你们单位写的"稿件。

**核心能力：**

- **多格式素材导入：** 支持Word、PDF、TXT等主流格式，可批量导入用户单位历史新闻稿、工作简报、党建文稿、医院动态、领导讲话稿等存量素材，无需手动整理，系统自动解析并去噪，降低素材归集成本
- **精准风格复刻：** 基于RAG检索增强生成技术，智能学习用户单位专属行文风格、固定话术、政治口径、格式规范，包括但不限于：
  - 语体特征：正式度、简洁度、句式偏好（长句/短句、主动/被动）
  - 用词习惯：高频词汇、惯用表达、特定称谓（如"我街道""本院""我支部"）
  - 结构模式：标题命名习惯、段落组织方式、结尾格式
  - 口径规范：政治表述定式、医疗术语规范、党建标准表述
  - 经过多轮训练后，生成稿件与用户历史稿件风格一致性达90%以上（基于双盲人工评测，评测维度包括用语习惯、句式结构、整体文风3个维度），避免通用AI的"模板化、空洞化"问题

- **分层训练适配：** 支持按多维标签分层训练，例如：
  - 按稿件类型：党建稿、政务通知、医院动态、工作总结
  - 按发布渠道：官网（正式严谨）、公众号（兼具可读性）、内部简报（简洁高效）
  - 按受众对象：上级汇报（突出成效和数据）、群众宣传（通俗易懂）、内部通报（问题导向）
  - 确保不同场景下的稿件适配度，满足多样化撰稿需求

- **素材库管理：** 自动对导入素材进行分类归档、关键词标注，支持按时间、类型、关键词检索，支持素材更新、删除，形成用户单位专属素材知识库，方便后续撰稿时快速调用，同时采用数据加密存储，保障素材隐私安全，避免外泄

**参考方法：**
- 检索策略借鉴LangChain/LlamaIndex生态的HyDE检索、Multi-Vector Retrieval机制
- 分层训练思路参考Anthropic Claude的System Prompt分层注入（System Prompt + Task Prompt + User Context）

### （二）高效稿件生成功能（核心价值）

**功能目标：** 将传统数小时的撰稿工作压缩至几分钟，效率提升75%以上（基于实际使用场景的A/B测试数据：传统撰稿 vs 星原撰稿耗时对比）。

**核心能力：**

- **关键词快速出稿：** 用户仅需输入核心关键词、事件要点、时间、人物等关键信息（支持自由文本输入或结构化字段输入），1—3分钟即可生成完整稿件初稿，涵盖标题、导语、正文、结尾，无需手动搭建框架。系统自动根据用户历史文风生成初稿，而非通用模板填充

- **多场景稿件模板：** 内置政务、医院、党建等垂直领域专属模板，覆盖通知、报告、总结、新闻动态、党建心得、医疗科普、会议纪要等70+类常用稿件，用户可直接选用模板，输入关键信息即可生成初稿，进一步提升出稿效率

  | 领域 | 模板示例 | 数量 |
  |------|---------|------|
  | 政务 | 通知、通报、报告、请示、纪要、函、工作简报、政务新闻、工作总结、述职报告等 | 25+ |
  | 医院 | 医院新闻、健康科普、义诊通知、医护事迹、科室动态、医德医风等 | 20+ |
  | 党建 | 主题党日新闻、党建总结、党课讲稿、学习心得、三会一课记录等 | 15+ |
  | 通用 | 会议纪要、工作计划、内部通知、宣传推文等 | 10+ |

- **灵活编辑优化：** 生成的初稿支持在线编辑器实时修改，包含以下能力：
  - 段落调整：拖拽排序、合并拆分
  - 语句修改：联想替换、一键润色
  - **文风微调：** 一键调整稿件正式度（正式/半正式/简明）、篇幅（精简/标准/详细），适配不同场景行文要求
  - 版本对比：支持查看修改前后对比，避免误操作

- **批量生成能力：** 支持一次性输入多个关键词或多个事件要点（如批量导入本周活动列表），批量生成多篇不同稿件，适配用户高频发稿需求，尤其适合街道、医院、党建办等每日需发布多篇动态的单位

**参考方法：**
- 百度文心一言"知识增强"模板化生成策略
- 新华智云"媒体大脑"事件驱动自动写作流程

### （三）内容合规与校对功能（风控核心）

**功能目标：** 确保每一篇发出的稿件在政治口径、行业术语、行文格式上零差错。

**核心能力：**

- **多层敏感词与口径审核：**
  - **第一层 — 通用禁用词库：** 内置新华社新闻采编禁用词库（季度同步更新）
  - **第二层 — 行业专属禁用词库：** 政务/党建/医疗领域专属禁用词和规范表述（如医疗稿中不得出现的绝对化疗效承诺、党建稿中的标准政治表述）
  - **第三层 — 用户自定义词库：** 支持导入用户单位内部敏感词、领导审阅偏好、专属口径要求
  - **审核方式：** 生成稿件时自动触发三层过滤，敏感词标红高亮，提供规范替代建议，审核不通过则阻止发布，规避合规风险

- **格式自动规范：**
  - 严格遵循《党政机关公文格式》（GB/T 9704-2012）及医院、党建系统文稿格式要求
  - 自动规范：字体（标题方正小标宋、正文仿宋）、字号、行距（28磅）、段落间距、页边距、发文机关标识、发文字号、版记等
  - 将公文格式错误率降低75%以上（基于N篇公文格式校验结果对比），无需人工反复校对格式
  - 支持导出为标准格式文件（Word/PDF），可直接用于发文系统

- **人工审核留痕：**
  - 支持用户在审核模式下逐段审阅稿件，标注修改意见（批注+修订模式）
  - 审核记录自动留存，包括：审核人、审核时间、修改内容、审核意见
  - 形成"AI初稿生成→撰稿人初审→审核人审核→管理员终审→发布"的合规闭环
  - 明确责任划分，确保稿件发布前无违规、无差错，满足政务/医院/党建审计要求

- **错别字与语法校对：**
  - 自动检测稿件中的错别字、语法错误（搭配不当、成分残缺）、标点错误（中英文混用、全半角混用）
  - 提供修改建议，支持一键采纳
  - 同时优化语句流畅度，避免"机器翻译感"，提升稿件整体质量

**参考方法：**
- 人民网"AI写稿评测基准"中的政治表述准确性评估维度
- 中国信通院"可信AI"大模型写作能力评测标准中的合规性指标
- 国家网信办《生成式人工智能服务管理办法》合规框架

### （四）数据安全与合规保障（独立安全章节）

**功能目标：** 满足政务、医院、党建单位对数据主权与信息安全的严格要求。

**核心能力：**

- **数据加密与隔离：**
  - 传输加密：全链路HTTPS/TLS 1.3加密传输
  - 存储加密：用户素材、生成稿件、知识库均采用AES-256加密存储
  - 多租户隔离：不同用户单位的数据物理或逻辑隔离，确保无跨租户数据泄露风险
  - 数据不留存选项：用户可设置生成稿件的服务端留存策略（定时自动删除/手动删除）

- **部署模式：**

  | 维度 | 云端SaaS版 | 本地私有化版 |
  |------|-----------|-------------|
  | 部署方式 | 云端多租户，即开即用 | 部署于用户内网服务器，数据完全本地留存 |
  | 运维要求 | 零运维，服务商全托管 | 需用户提供服务器资源，服务商协助运维 |
  | 上线周期 | 1—3个工作日 | 1—2周（含部署+初始化训练） |
  | 适用场景 | 常规政务/医院/党建单位 | 高合规要求、涉密单位、军区、公安等 |
  | 数据主权 | 数据存储在服务商云端，加密隔离 | 数据100%本地留存，满足强数据主权诉求 |

- **等保与合规认证：**
  - 云端版通过等保2.0三级测评（计划中/已通过）
  - 私有化版配合用户单位完成等保适配
  - 符合《个人信息保护法》《数据安全法》要求
  - 符合《医疗卫生机构网络安全管理办法》对医疗数据的管理要求
  - 算法备案：已完成/计划完成生成式AI服务算法备案（网信办）
  - 生成内容标识：所有AI生成稿件注明AI辅助生成标识（如"本文由AI辅助生成，经人工审核"），满足《生成式AI服务管理暂行办法》要求

- **信创适配：**
  - 支持国产CPU（鲲鹏、飞腾、海光）部署
  - 支持国产操作系统（麒麟、统信UOS）
  - 支持国产数据库（达梦、人大金仓、OceanBase）
  - 满足信创目录要求，适配政务信创替代进程

- **权限管理：**
  - 支持多账号体系，按岗位分配角色权限：

  | 角色 | 权限范围 |
  |------|---------|
  | 撰稿岗 | 素材上传、稿件生成、稿件编辑、个人稿件记录查看 |
  | 审核岗 | 稿件审核、修改批注、审核记录查看、所属部门稿件统计 |
  | 管理员 | 全部权限 + 用户管理 + 操作日志查看 + 词库管理 + 模板管理 |

  - 敏感操作（删除素材、导出全量数据）需管理员二次确认
  - 完整操作日志留存，支持审计追溯

**参考方法：**
- 国际：GDPR数据保护框架、HIPAA医疗数据隐私标准、ISO 27001信息安全管理体系
- 国内：《数据安全法》《个人信息保护法》、等保2.0、《医疗卫生机构网络安全管理办法》

### （五）闭环迭代与增值功能（长期价值）

**功能目标：** 让系统随使用持续进化，长期降低人工修改成本。

**核心能力：**

- **定稿回流迭代：** 用户审核修改后的定稿稿件，经用户确认后自动回流至智能体的学习库，持续强化智能体对用户文风、口径、修改偏好的记忆，形成"生成—审核—再学习"闭环。效果：用户使用3个月后，人工修改率平均下降60%以上（基于试点单位使用数据）

- **稿件润色与续写：**
  - 润色：支持对人工已修改的稿件进行二次润色优化，提升语句严谨性、专业性，同时保持用户已有的修改内容不变
  - 续写：针对未完成的稿件，输入后续要点即可从断点处继续生成，保持文风连贯，适配加急稿件场景

- **多端适配：**
  - 支持PC端（浏览器）、移动端（H5/小程序）登录使用
  - 支持断点续写：PC端未完成的稿件，可在移动端继续编辑
  - 适配用户外出办公、紧急撰稿场景（如领导下基层调研后需立即发稿）

- **部署灵活：** （详见第（四）节部署模式对比表）
