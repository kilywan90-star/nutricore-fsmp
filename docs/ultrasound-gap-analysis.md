# 超声语音报告系统 — 完整方案 vs 现有代码 差距分析

## 覆盖度总览

| 层级 | 已有 | 不完整 | 缺失 |
|------|------|--------|------|
| 基础能力 | 11 | 2 | 7 |

## 逐条分析

### 一、核心设计底线

| 要求 | 状态 | 现状 | 需要做什么 |
|------|------|------|------------|
| 病历隐私院内私有化 | 缺失 | DeepSeek API公网调用，数据出域网 | 加数据脱敏层，或后续部署本地LLM |
| 全流程操作留痕 | 缺失 | 无audit_log | 新增 audit_log 表，记录每步操作 |
| 规则库+LLM双重校验 | 不完整 | 两条路径独立运行，无交叉校验 | 加 post-hoc 校验函数 |
| 人工兜底 | 已有 | 前端"超声所见"可编辑，审核卡片可删除 | 够用 |

### 二、系统前置初始化

| 要求 | 状态 | 现状 |
|------|------|------|
| HIS对接 | 缺失 | 手动录入姓名/年龄/检查类型 |
| EMR对接 | 缺失 | save仅存本地SQLite，无EMR写入 |
| PACS对接 | 不完整 | send存本地+日志，无HL7/FHIR |
| 报告模板库(按部位) | 已有 | templates.py 5类+CSV模板表 |
| 医疗规则库 | 已有 | asr_correction.py+template_fetal/filler |
| 语音引擎(医疗ASR) | 已有 | 阿里云百炼 qwen3-asr-flash |
| TTS语音播报 | 缺失 | 未实现 |
| 大模型私有化部署 | 缺失 | 当前用DeepSeek公网API |

### 三、核心执行流程 6阶段

| 阶段 | 要求 | 覆盖度 | gap |
|------|------|--------|-----|
| 1.医生前置操作 | 绑定病人+选部位 | 50% | 已有选患者+填检查类型，但无HIS自动拉取+部位下拉选择 |
| 2.语音采集→ASR | 录音+ASR+留痕 | 75% | ASR已含纠错，语音原始文件已存audio_backups，缺少转写文本+修改日志链路 |
| 3.固定规则库清洗 | 术语标准化+字段提取+空值标记 | 85% | asr_correction+template_fetal已覆盖大部分，缺必填项检查 |
| 4.LLM智能处理 | 语义理解+模板匹配+填充 | 70% | llm_client已有，但未传递规则清洗后的文本 |
| 5.双重检查校验 | 规则+LLM交叉验证 | 10% | 完全缺失 |
| 6.医生复核→归档 | 预览+编辑+确认+留痕 | 40% | 前端可编辑确认，但无修改diff记录，无EMR同步 |

### 四、核心模块分工

| 模块 | 现有状态 |
|------|----------|
| 固定规则库 | 85%完成 (asr_correction + template_fetal + template_filler) |
| 医疗专用LLM | 60%完成 (DeepSeek公网, 非医疗微调) |

### 五、异常兜底

| 场景 | 状态 | 做法 |
|------|------|------|
| ASR失败 | 已有 | 前端手动输入text |
| LLM异常 | 缺失 | 无fallback — 需加规则单独兜底 |
| 模板匹配失败 | 已有 | LLM free-text兜底 |
| 网络中断 | 缺失 | 无localStorage缓存 |

## 优先级排序

### P0 (本周可完成，影响最大)

1. **操作留痕** — audit_log表，记录每步操作 → 合规必备
2. **LLM异常兜底** — LLM调用失败时规则库单独生成基础报告
3. **必填项检查** — 部位+主要病灶为空时前端高亮提醒
4. **部位选择** — 前端加检查部位下拉(已有templates数据)

### P1 (下周，提升质量)

5. **规则+LLM交叉校验** — 规则结果传给LLM做一致性校验
6. **数据脱敏** — 传给LLM前remove姓名等PII
7. **修改留痕** — 医生编辑后记录diff

### P2 (后续迭代，需外部依赖)

8. HIS/EMR/PACS对接 — 需要医院接口文档
9. 本地LLM部署 — 需要GPU服务器
10. TTS语音复核 — 可用阿里云TTS

## 总结

完整方案的**核心骨架已经具备**（11个模块），缺失的主要是：
- 合规留痕类（audit_log, edit_history）
- 外部对接类（HIS/EMR/PACS）
- 高级校验类（双检交叉验证）

建议**先补齐P0再跑一遍测试**，P1/P2按需推进。
