### 1.2 角色与职责矩阵

| **系统管理员** | 用户管理、权限配置、规则维护 | 账号开通/冻结、审核规则配置 | 系统配置权 |

### 3.2 核心选型决策依据

#### AI 引擎

| 组件 | 选型 | 备选 | 理由 |
|------|------|------|------|
| **主力 LLM** | DeepSeek-V3 API | 通义千问 Qwen3 | 百万 token 几块钱、中文理解强、支持 JSON Schema 约束输出 |
| **本地小模型** | Qwen3-8B (vLLM 部署) | ChatGLM-6B | 审核分类、意图识别等高频低延迟场景，零 API 成本 |
| **Embedding** | BGE-M3 (本地) | text2vec-large-chinese | 支持 8192 token 长度，中英文双语，MTEB 中文榜首 |
| **OCR** | PaddleOCR (本地) | Tesseract | 中文识别率 97%+，支持表格识别，完全离线 |
| **ASR 语音识别** | Whisper large-v3 (本地) | 阿里云 ASR | 中文准确率高，本地部署无数据外泄 |
| **TTS 语音合成** | CosyVoice / Edge-TTS | 讯飞 TTS | 情感语音合成质量高，支持声音克隆(数字人) |
| **多模态理解** | Qwen-VL / InternVL2 | GPT-4o | 图文理解（广告合规检测中的图片分析），国产合规 |

#### 合规引擎

| 能力 | 实现方式 | 说明 |
|------|---------|------|
| **广告合规检测** | 规则引擎(80%) + LLM(20%) | 规则覆盖 6 大红线的关键词和模式匹配，LLM 兜底语义理解 |
| **隐私脱敏** | 正则 + NER 模型 + 规则 | 三层策略：模式匹配(身份证/手机) → 实体识别(姓名/地名) → 上下文判断 |
| **AI 内容标识** | 中间件注入 | 文本自动加"AI生成"标注、图片加水印层、视频首帧覆盖、元数据写入 |
| **数字水印** | 盲水印 + 明水印 | 明水印防截屏传播，盲水印(频域)用于泄露溯源 |
| **医学事实核查** | RAG + 医学知识库 | 将待发布内容与权威医学知识库做语义比对，标记存疑断言 |

#### 后端

| 组件 | 选型 | 理由 |
|------|------|------|
| **Web 框架** | FastAPI (Python 3.12) | 异步高性能、自动 OpenAPI 文档、Pydantic 验证、生态成熟 |
| **任务队列** | Celery + RabbitMQ | 异步处理（视频转码、多渠道分发、定时发布）、重试、优先级 |
| **ORM** | SQLAlchemy 2.0 (async) | 异步支持、成熟稳定、Alembic 迁移 |
| **工作流引擎** | 自研（基于状态机） | 审核流程不复杂但需要高度可配置，轻量状态机优于引入 Camunda |
| **实时通信** | WebSocket (FastAPI 原生) | 审核通知、发布状态实时推送 |

#### 前端

| 组件 | 选型 | 理由 |
|------|------|------|
| **框架** | React 18 + TypeScript | 生态最大、Ant Design 配套最优 |
| **UI 库** | Ant Design 5 | 中后台管理系统首选，表格/表单/流程组件丰富 |
| **富文本编辑器** | TipTap (基于 ProseMirror) | 支持医学公式、图文混排、AI 辅助写作插件 |
| **视频播放器** | Video.js + 自研裁剪组件 | 支持打点标注、帧截图、多分辨率 |
| **状态管理** | Zustand | 轻量、TS 友好 |
| **数据请求** | TanStack Query (React Query) | 缓存、去重、乐观更新 |

#### 数据存储

| 数据类型 | 存储 | 说明 |
|---------|------|------|
| **业务数据**（用户/内容/审核/排期） | PostgreSQL 16 | 关系型数据，需要事务和强一致性 |
| **向量数据**（知识库/语义检索） | Milvus 2.4 | 十亿级向量检索，支持 IVF/HNSW 索引，带 metadata 过滤 |
| **文件/素材**（图片/视频/文档/附件） | MinIO (S3 兼容) | 本地部署，对象存储，支持版本管理 |
| **缓存/会话** | Redis 7 | 权限缓存、限流计数、发布队列 |
| **日志/搜索** | Elasticsearch 8 | 操作审计日志、全文搜索（历史内容检索） |

### 3.3 不选型的决策

| 不选 | 原因 |
|------|------|
| ~~微服务架构~~ | 医院部署环境通常 1-2 台服务器，微服务运维成本过高。用模块化单体 + 消息队列解耦即可 |
| ~~Kafka~~ | 医院量级不需要。RabbitMQ 足够 |
| ~~Kubernetes (一期)~~ | 一期用 Docker Compose 单机部署，二期有集群需求再上 K8s |
| ~~MySQL~~ | PostgreSQL 在 JSON 查询、全文检索、向量扩展(pgvector)方面更优 |
| ~~Java/Go 后端~~ | Python 在 AI/LLM 集成上零摩擦，开发效率碾压。性能瓶颈在 LLM API 调用和视频转码，不在语言 |
| ~~微前端~~ | 单体前端足够，医院端用户量 < 500，不需要模块联邦 |

**检测链路（流水线模式）**：

```
内容输入
  │
  ├── [1] 文本预处理：统一编码、去除控制字符
  ├── [2] 规则检测（快速，<50ms）：关键词、正则、敏感词
  │       └── 命中 → 记录违规定位
  ├── [3] 隐私扫描（快速，<100ms）：身份证/手机/姓名/病历号
  │       └── 命中 → 自动脱敏或标记需人工确认
  ├── [4] LLM 语义检测（慢速，1-3s）：广告意图、疗效承诺
  │       └── 需 LLM → 发到 LLM Gateway
  ├── [5] 链接/二维码扫描：解析所有 URL、检测跳转目标
  ├── [6] AI 标识注入：如果内容由 AI 生成，注入显式+隐式标识
  ├── [7] 水印注入：操作人+时间戳+用途
  └── [8] 生成检测报告
```

## 八、技术风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|:---:|:---:|---------|
| 医院网络环境复杂，部署困难 | 高 | 上线延期 | Docker Compose 一键部署，离线安装包，提供部署巡检脚本 |
| OCR 对扫描件/水印文件准确率低 | 中 | 内容生产卡点 | 电子版优先，扫描件做预处理（去噪/纠偏/超分），降级为人工录入 |
| LLM API 不稳定或涨价 | 中 | 服务中断/成本超预算 | 多模型热备（DeepSeek→通义千问→本地Qwen3），本地小模型兜底 |
| 不同省份卫健委有追加合规要求 | 高 | 功能不通用 | 审核规则全部配置化，提供省份规则模板 |
| 渠道 API 频繁变动 | 中 | 分发失败 | Adapter 模式隔离，渠道变更只影响单个 Adapter |
| 患者数据泄露 | 低 | 法律/声誉灾难 | 多层防护 + 隐私脱敏 + 审计日志 + 定期渗透测试 |
