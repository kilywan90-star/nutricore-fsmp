## 1. 产品定位与全景

**一句话定位**：面向内分泌科的全病程 AI 协诊系统，主治医生的数字分身，三位一体覆盖患者、医生、医共体。

**核心定位**：
- 不是"聊天机器人"，是**循证医学驱动的临床决策系统**
- 不是"取代医生"，是**放大医生能力**的效率杠杆
- 不是"单院工具"，是**医共体能力下沉**的数字化载体

### 三端核心功能矩阵

| 阶段 | 患者端 (小程序) | 医生端 (工作站/移动) | 医共体端 (管理后台) |
|------|----------------|---------------------|-------------------|
| **院前** | 风险评估问卷、AI分诊、科普推送 | 预问诊摘要、高危标记 | 社区筛查汇聚、转诊预登记 |
| **院中** | 报告AI解读、住院日程、用药说明 | 辅助诊断推理、病历生成、指南速查 | 远程会诊调度、床位查询 |
| **院后** | 血糖记录、饮食运动管理、预警 | 患者分层看板、异常标记、随访助手 | 基层签约协作、管理报表、质量考核 |

### 核弹用户旅程（2型糖尿病患者）

```
社区筛查 → 风险评估(高危,自动转诊建议)
  → 院前预问诊(患者端) → 预问诊摘要推送医生
    → 诊中辅助诊断 + 用药审核 + 病历生成
      → 院后AI健康教练 + 异常预警 + 定期随访
        → 基层签约医生协同管理
```

## 2. 循证医学知识底座

### 指南层级

```
国际：ADA糖尿病诊疗标准(年度) / IDF管理共识 / WHO慢病防控 / NICE 2型糖尿病指南
国家：中国2型糖尿病防治指南 / 国家基层糖尿病防治管理指南
      / 中国防治慢性病中长期规划 / 糖尿病分级诊疗技术方案
      / DRG/DIP内分泌科付费指引
科室：院内诊疗路径/处方集/SOP (本地化覆盖层)
```

### 规则引擎设计

- **三层结构**：分型/分期规则 → 治疗路径引擎 → 质量管理规则
- **硬规则 vs 软建议**：禁忌症/危急值是硬阻断，用药推荐是软建议（人机确认）
- **版本化**：指南更新 → 规则版本化 → 历史决策可复现
- **本地化**：国际→国家→科室逐级覆盖，未覆盖向上查找
- **可解释**：每个AI建议附带"依据哪份指南哪条建议"

## 3. 技术架构

### 整体分层

```
接入层：患者小程序(H5) │ 医生工作站(Web) │ 医共体管理后台(Web)
        ───────────────── API Gateway (鉴权/限流/审计/HL7-FHIR转换)
服务层：对话编排 │ 临床决策引擎 │ 慢病管理引擎 │ Agent协作总线
        ───────────────── 数据与知识层 ─────────────────
院内部署区：            │  云端协作区：
  HIS/EMR/LIS/PACS适配器 │  医学知识图谱(Neo4j)
  临床数据中心(CDR)      │  LLM推理服务(多模型路由)
  结构化规则引擎         │  医共体协同DB(脱敏)
                         │  向量数据库(Milvus)
```

### 数据安全硬线

- PHI明文仅存CDR加密列，密钥医院管理
- AI推理输入脱敏（姓名/身份证/住址/电话）
- 医共体协同仅传递脱敏临床摘要+业务token
- 全链路审计日志

### Agent 矩阵

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| 分诊导诊 | 症状→分诊建议 | 自然语言主诉 | 科室/检查/紧急程度 |
| 预问诊 | 结构化病史采集 | 患者自述 | 现病史/既往史/家族史JSON |
| 辅助诊断 | 指南匹配+鉴别推理 | 问诊JSON+检查 | 分型建议/鉴别诊断/置信度 |
| 用药审核 | 处方合理性审核 | 诊断+处方+肾功能 | 通过/警告/禁忌+依据 |
| 病历生成 | 诊中对话→文书 | 医患对话+检查 | SOAP/住院志/出院小结 |
| 健康教练 | 长期行为干预 | 血糖+饮食记录 | 个性化建议+预警 |
| 随访管理 | 自动化随访 | 患者分层标签 | 随访计划+异常标记 |

### 混合部署数据流

| 数据类 | 存储位置 | 流向规则 |
|--------|---------|---------|
| 患者PHI | 仅院内 | 不出院，云端不可见 |
| 病历 | 仅院内 | 结构化脱敏后可入AI推理 |
| 检查报告 | 院内主，云端副本 | 图像不入云，报告文本可入推理 |
| 指南规则 | 云端主，院内镜像 | 定期同步规则版本 |
| 知识图谱 | 云端 | — |
| LLM推理 | 云端执行 | 输入脱敏，结果写回院内 |

## 4. 医院系统集成

### 三级降级策略

| 等级 | 条件 | 方式 | 周期 |
|------|-----|------|------|
| L1 理想 | 支持FHIR R4 | FHIR API实时查询 | 2-4周 |
| L2 标准 | 传统HIS/EMR，DB只读 | DB视图+HL7 v2 MQ | 4-8周 |
| L3 降级 | 封闭系统，仅PDF/Excel | OCR结构化+手动补录 | 2-3天 |

适配层向上暴露统一FHIR模型，上层业务不感知差异。

### 预留集成点

- **慢病管理专病系统**：FHIR `CarePlan`/`Goal`/`Questionnaire` 双向同步
- **区域健康信息平台**：国家卫健委区域卫生信息平台技术规范，ESB+SOAP/HTTPS
- **医共体三级部署**：市级(完整版) │ 县级(完整版,核心) │ 乡镇(轻量版,弱网可用)

## 5. 商业模式

### 收入结构

软件授权(~55%) + 实施服务(~25%) + 持续运营(~20%)

### 定价

| 版本 | 适用 | 参考年费 |
|------|-----|---------|
| 轻量版 | 乡镇卫生院 | 8-15万/年 |
| 标准版 | 县级医院(核心) | 40-80万/年 |
| 高级版 | 市级三甲 | 100-200万/年 |
| 医共体套件 | 1牵头+N基层 | 标准版+N×3万/基层 |

### 价值映射

- 病历书写效率：15min→3min → 日接诊量+20-30%
- 慢病患者管理量：500→2000/医生
- HbA1c达标率+15-20% → 等级评审/重点专科验收

### 预算来源

医院信息化预算 / 卫健委慢病防控专项资金 / 医共体建设专项 / 医保DRG结余留用

## 6. 风险合规

| 风险 | 等级 | 应对 |
|------|-----|------|
| 医疗数据安全 | **高** | 院内数据不出院、TLS1.3、等保三级 |
| AI误诊责任 | **高** | 置信度标注+依据溯源+人机确认强制中断点 |
| 医疗器械属性 | **高** | 初期定位"辅助决策支持"，咨询药监局分类界定 |
| 指南过期 | 中 | 规则版本化+自动更新提醒+超期锁定 |
| 医院信息化差 | 中 | L3降级方案兜底 |
| 医共体数据主权 | 中 | 联邦查询+数据使用协议 |
| 医生抵触 | 低 | 定位"助手"+"效率增益"而非替代 |

## 7. 分阶段交付路线

### M1 最小可用（第1-3月）

- 患者端：风险评估 + AI报告解读 + 用药提醒 + 血糖记录 + 健康教练
- 医生端：患者列表 + 指标趋势 + 异常预警
- 底座：1家医院HIS/EMR/LIS适配 + 2型糖尿病核心路径规则引擎
- **验收**：1个主治医生管理≥200慢病患者

### M2 临床闭环（第4-6月）

- 预问诊 + 辅助诊断推理 + 用药审核 + 病历生成
- 并发症风险分层预警
- **验收**：单个患者诊疗时间降低40%

### M3 医共体辐射（第7-9月）

- 双向转诊调度 + 远程会诊辅助
- 基层轻量版 + 医共体管理看板
- 慢病专病系统/区域平台对接
- **验收**：1个医共体(1县+N乡镇)全链路跑通
