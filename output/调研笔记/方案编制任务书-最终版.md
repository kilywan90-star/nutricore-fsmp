## 二、建设策略核心约束（贯穿全方案）

### 2.1 五项铁律

| 铁律 | 含义 | 方案中的落地要求 |
|------|------|-----------------|
| **查漏补缺** | 先摸清现有系统家底，只建没有的、补足薄弱的 | 每个建设模块必须先回答：现状有什么、缺什么、为什么必须建 |
| **避免重复建设** | 已有系统能用则用、能扩则扩，同类功能不重复投资 | 存量系统评估表：标注每个已有系统的"保留/升级/替换"决策及理由 |
| **不搞大拆大建** | 不推倒重来，最大化利旧现有硬件、网络、数据、人员能力 | 利旧率目标：硬件≥60%、网络≥80%、数据100%迁移 |
| **适配改造优先** | 现有系统通过接口改造、功能扩展、配置优化来满足新需求 | 新建 vs 改造决策树：先评估改造可行性→仅当改造不可行时才新建 |
| **性价比突出** | 每花一分钱都要对应可量化的回报或刚性的合规需求 | 标注投入金额 vs 预期年回报，优先实施回报周期<18个月的项目 |

### 2.6 常见失败模式与规避

| 失败模式 | 案例教训 | 阿坝规避策略 |
|----------|---------|------------|
| 贪大求全、一期铺太开 | 一次性全省铺开→系统崩溃、基层抵触 | 一期只做4试点县，跑通后再推广 |
| 建完不用、系统空转 | 投2000万建平台，上线1年后登录率<10% | 信息化使用率纳入院长考核、月度通报排名、设"用得好"奖金 |
| 重硬轻软、数据不通 | 大量硬件采购但HIS对接失败 | 预留215万专项用于HIS接口开发 |
| AI当摆设、医生不信任 | AI部署后医生从不参考 | AI上线前先做双盲对比测试+本地数据证明准确率 |
| 供应商锁定、后期被动 | 全部委托一家供应商 | 接口全部采用HL7/FHIR开放标准、合同约定二开权利 |

### 阶段一：存量摸底与需求诊断（只读调研，不写方案）

#### T1. 阿坝州存量信息化家底普查

逐县（13县+州本级）摸清以下家底，输出**存量系统评估表**：

| 县/机构 | 系统名称 | 供应商/品牌 | 上线年份 | 覆盖范围 | 使用状态 | 保留/升级/替换 | 决策理由 |
|---------|----------|------------|---------|---------|:---:|:---:|------|
| 州人民医院 | HIS | 重庆中联ZLHIS | 20XX | 全院 | 在用 | 保留+升级 | 主流品牌，可通过接口适配接入州平台 |
| XX县 | XX系统 | XX | 20XX | — | 闲置 | 替换 | 品牌小众，接口不开放 |

**决策规则**：
- **保留**（>50%存量系统）：主流品牌、接口开放、使用状态良好 → 不做任何改动
- **保留+适配改造**（约30%）：主流品牌但版本老旧/接口需开发 → 投入少量改造费对接州平台
- **替换**（<20%）：小众品牌、接口封闭、已停维、使用率低 → 统一替换为标准系统

**利旧率目标**：
- 硬件利旧率 ≥ 60%（服务器/存储/网络设备/终端）
- 网络利旧率 ≥ 80%（电子政务外网已覆盖大部分乡镇）
- 数据利旧率 = 100%（历史诊疗数据全部迁移至新平台）

#### T2. 阿坝州现状痛点诊断

从以下维度分析，每个维度输出**量化现状 + 突出短板 + 改造空间评估**：

- **医疗卫生**：机构/床位/人力/设备/服务量/县域就诊率/基层诊疗占比
- **医疗保障**：参保/基金收支/外转率/DIP试点/智能审核现状
- **医药管理**：药品采购模式/基药使用率/中心药房/处方审核
- **医改推进**：医共体建设阶段/八统一落地/三医联动
- **健康管理**：慢病管理率/家医签约履约率/公卫/妇幼
- **信息平台**：HIS品牌分布/互联互通评级/电子病历评级/已有平台/数据孤岛/闲置系统
- **招标中标**：近3年13县信息化招标项目、中标方、金额、建设内容（**重点标注：哪些已建成的本次可直接利旧**）

#### T10. 建设方案撰写要求

每个建设模块必须包含6个标准段落：

1. **存量盘点**：该领域目前有什么、使用状态
2. **差距分析**：缺什么、为什么缺、不建会怎样
3. **改造策略**：优先适配改造现有系统→仅当不可行时才新建
4. **建设方案**：具体建设内容（新建部分）+ 适配改造方案（利旧部分）
5. **利旧清单**：哪些硬件/软件/数据/人员可直接复用
6. **投入产出**：投资金额 vs 预期年回报（或合规必须性），标注回报周期（<18个月=优先）

**三大最佳实践模式需在方案中明确体现**：

**模式一：三级漏斗AI审核架构**（适用医保审核/处方审核场景）
```
100%数据 ──→ [L1: 规则引擎] ──→ ~15%可疑
               >500条规则, <1ms/条, 零推理成本
                │
                ▼
            [L2: 轻量AI分类] ──→ ~5%高度可疑
               BERT本地微调, <100ms/条, 极低成本
                │
                ▼
            [L3: LLM深度推理] ──→ ~2%确认问题
               仅疑难case才调用, 年API费用<10万元
```
> 参考案例：梧州(34万份AI全量审核)、湘潭(16万条数据、问题病历≈5%)

**模式二：AI初筛+医生复核模式**（适用影像AI场景）
```
基层拍片 → AI秒级初筛（标注+分级+报告草稿）
         → 阴性：AI自动生成报告，医生一键确认（节省80%工作量）
         → 阳性：AI标注区域→推送医生复核→医生修正后发出
         → 疑难：AI预分析→推送专家会诊
```
> 参考案例：重庆(阅片效率数十倍)、南皮(设备利用率↑100%)

**模式三：AI健管智能体+家医协同模式**（适用慢病管理场景）
```
AI处理80%常规随访(语音外呼+数据录入+初步分析)
→ 家医聚焦20%复杂case(异常结果审核+个性化干预+面对面服务)
→ 协同效果：人均管理患者数提升3-5倍，规范管理率提升20%+
```
> 参考案例：西青(血糖达标率6.2%→36.9%)、江西(覆盖省域全覆盖)

## 五、执行纪律

1. **顺序铁律**：严格按阶段一→二→三→四→五顺序执行，每个阶段完成后确认再进入下一阶段
2. **决策节点**：阶段二完成后（输出3套大纲），选择一套作为主方案精写；阶段三按章节逐章推进
3. **禁止**：没有数据支撑不得编造具体数字；不确定的数据标注"待核实"
4. **质量底线**：方案需可向州政府分管领导直接汇报；每项建设内容需有政策或案例依据
5. **利旧绝对优先**：能改不建、能扩不买、能复用不采购——任何"新建"决策必须在存量评估中证明"无存量可改造"
