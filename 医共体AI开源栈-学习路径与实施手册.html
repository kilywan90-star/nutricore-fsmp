第1章 W1：环境准备 — Hyper-V + Ubuntu + Docker

1.1 启用Hyper-V（Windows 11 Pro已内置）

# 以管理员身份打开PowerShell，执行：

Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All

# 重启电脑生效

1.2 下载Ubuntu Server 24.04 LTS

# 官方下载地址（在宿主机浏览器打开）：
https://releases.ubuntu.com/24.04/ubuntu-24.04.2-live-server-amd64.iso

# 保存到 E:\iso\ 目录

1.3 创建Hyper-V虚拟机

  • 打开 Hyper-V 管理器（Win键搜索"Hyper-V"）
  • 右侧点击「新建」→「虚拟机」
  • 名称：dify-lab | 代：第2代 | 内存：32768 MB（不要勾选动态内存）
  • 网络：选择 Default Switch（NAT模式，可访问外网）
  • 虚拟硬盘：新建，大小 200GB，路径 E:\vm\dify-lab\
  • 安装选项：从映像文件安装，选择刚下载的 Ubuntu ISO
  • 完成后右键虚拟机 →「设置」→ 处理器 → 8个虚拟处理器
  • 右键 →「连接」→「启动」，进入Ubuntu安装

    • 1.4 Ubuntu安装要点

    # 安装过程中关键选择：
1. 语言: English
2. 安装类型: Ubuntu Server (minimized)  ← 选最小化，节省资源
3. 网络: 默认DHCP即可
4. 磁盘: Use entire disk (默认)
5. 用户: difyadmin / 你的密码
6. 安装OpenSSH: YES (勾选)  ← 重要！后续通过SSH操作

    1.5 配置SSH登录（宿主机→虚拟机）

    # 虚拟机装好后，查看IP：
ip addr show eth0
# 假设IP为 172.x.x.x

# 在Windows宿主机打开 PowerShell/Terminal：
ssh difyadmin@172.x.x.x

# 配置免密sudo（可选）：
echo "difyadmin ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/difyadmin

    1.6 安装Docker环境（一键脚本）

    # SSH进入虚拟机后，依次执行：

# 1. 更新系统
sudo apt update && sudo apt upgrade -y

# 2. 安装Docker官方脚本
curl -fsSL https://get.docker.com | sudo bash

# 3. 添加当前用户到docker组（免sudo运行docker）
sudo usermod -aG docker $USER
newgrp docker

# 4. 验证
docker --version      # 应显示 27.x+
docker compose version # 应显示 v2.x+

# 5. 设置Docker开机自启
sudo systemctl enable docker

# 6. 配置国内镜像加速（可选但推荐）
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "3" }
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
    提醒：虚拟机重启后IP可能会变。建议在Hyper-V中给虚拟机设置静态MAC地址，或在路由器中做DHCP绑定。生产环境建议配置静态IP： sudo vim /etc/netplan/00-installer-config.yaml

    2.2 为什么不用Ollama，改用Xinference？

    对比维度OllamaXinference
    并发请求单请求排队，后续请求阻塞等待原生支持并发，适合多用户场景
    推理后端仅llama.cpp（GGUF格式）多后端：llama.cpp / Transformers / vLLM / SGLang 按需切换
    模型管理纯命令行，无界面Web UI可视化管理，一键加载/卸载/监控
    模型格式仅GGUF量化格式GGUF + PyTorch + GPTQ/AWQ + MLX 全格式支持
    Embedding/Reranker需单独拉取，管理分散统一管理，LLM + Embedding + Reranker一起管
    分布式部署单机支持多机分布式，未来医共体多院区可扩展
    API兼容自有API格式OpenAI兼容API，Dify原生支持，无需适配
    CPU性能仅llama.cpp（一般）llama.cpp后端（同等性能）+ 可按场景切换
    社区/文档英文为主中文生态，国内团队维护，文档完善
    生产就绪偏向个人开发者企业级，适合医共体正式部署
    结论：Ollama适合个人开发者快速体验，但在医共体场景（需要并发、可视化管理、生产稳定性）下，Xinference全面胜出。且Xinference的OpenAI兼容API可以直接对接Dify，无需额外适配层。

    2.3 安装Xinference（Docker方式）

    # Xinference（星环）— 开源、生产级模型推理平台
# 支持 llama.cpp(CPU优化) / Transformers / vLLM 三种后端
# 提供Web管理界面 + OpenAI兼容API

# 1. Docker部署（推荐，与Dify同一Docker网络）
docker run -d --name xinference \
  --restart always \
  -p 9997:9997 \
  -v ~/xinference-data:/root/.xinference \
  -v ~/xinference-cache:/root/.cache/huggingface \
  -e XINFERENCE_HOME=/root/.xinference \
  -e XINFERENCE_MODEL_SRC=modelscope \
  xprobe/xinference:latest

# 2. 检查日志，确认启动成功
docker logs -f xinference
# 看到 "Uvicorn running on http://0.0.0.0:9997" 即成功

# 3. 访问Xinference Web管理界面
# 浏览器打开: http://虚拟机IP:9997
# 可以看到模型管理控制台

# 补充：XINFERENCE_MODEL_SRC=modelscope 表示从ModelScope拉模型
# （国内网络比HuggingFace快很多，无需科学上网）
    备选方案：llama.cpp 纯命令行极简部署（如果觉得Xinference太重） 
    # llama.cpp server 模式 — 最轻量CPU推理，无Web界面
docker run -d --name llamacpp \
  --restart always \
  -p 8080:8080 \
  -v ~/models:/models \
  ghcr.io/ggerganov/llama.cpp:server \
  -m /models/qwen3-8b.Q4_K_M.gguf \
  --host 0.0.00 --port 8080

# API调用: curl http://localhost:8080/v1/chat/completions ...
# 然后在Dify中通过「OpenAI-API-compatible」供应商接入
# 缺点：没有管理界面，模型需手动下载GGUF文件

    2.4 通过Xinference Web界面加载模型

  • 浏览器打开 Xinference Web：http://虚拟机IP:9997
  • 左侧菜单 →「Launch Model」→ 选择模型
  • LLM模型：搜索 qwen3-instruct → 选择 8B/14B（GGUF格式，CPU优化）
  • 后端选择 llama.cpp（CPU推理最优，GGUF量化格式）
  • 量化版本选择 Q4_K_M（4bit量化，性能/精度最佳平衡，14B约9GB）
  • 点击「Launch」→ 等待模型下载和加载（首次约15-30分钟）
  • 同样操作加载 DeepSeek-R1-Distill-Qwen-7B（推理增强模型）
  • Embedding模型：搜索 bge-m3 → 后端选 Transformers → 加载
  • Reranker模型：搜索 bge-reranker-v2-m3 → 加载
    • 模型选择建议（CPU场景）：虚拟机无GPU时，务必选GGUF量化格式 + llama.cpp后端。 Q4_K_M量化是精度和速度的最佳平衡点。Qwen3-14B-Q4_K_M 需要约9GB内存，32GB虚拟机完全够用。

    2.5 在Dify中接入Xinference（OpenAI兼容API）

  • 登录Dify控制台 → 右上角头像 →「设置」→「模型供应商」
  • 找到「OpenAI-API-compatible」→ 点击「添加模型」
  • 模型名称：qwen3-instruct（与Xinference中名称一致）
  • API Endpoint：http://xinference:9997/v1
  • API Key：xinference（Xinference默认不需要真实Key，填任意值即可）
  • 同样添加 DeepSeek-R1模型
  • 在「模型供应商」→「Embedding模型」中同样用OpenAI-API-compatible接入bge-m3

    • 2.6 命令行方式加载模型（替代Web UI操作）

    # 也可以通过命令行加载模型，适合脚本化部署：

# 加载LLM（Qwen3 14B，GGUF格式，llama.cpp后端）
curl -X POST http://localhost:9997/v1/models \
  -H "Content-Type: application/json" \
  -d '{
    "model_engine": "llama.cpp",
    "model_name": "qwen3-instruct",
    "model_format": "ggufv2",
    "model_size_in_billions": 14,
    "quantization": "Q4_K_M",
    "model_uri": "qwen/Qwen3-14B-Instruct-GGUF"
  }'

# 加载Embedding模型（全精度，Transformers后端）
curl -X POST http://localhost:9997/v1/models \
  -H "Content-Type: application/json" \
  -d '{
    "model_engine": "Transformers",
    "model_name": "bge-m3",
    "model_uri": "BAAI/bge-m3"
  }'

# 查看已加载的模型列表
curl http://localhost:9997/v1/models

# 测试推理
curl http://localhost:9997/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3-instruct",

    3.2 在Dify中创建第一个知识库

  • Dify控制台 →「知识库」→「创建知识库」
  • 名称：基层常见病诊疗指南
  • 上传文档（支持PDF/Word/Markdown/TXT），首次建议上传3-5份常见病指南
  • 分段设置：自动分段与清洗 | 分段最大长度：800 tokens | 重叠：100 tokens
  • 索引方式：高质量模式
  • Embedding模型：选择 bge-m3（通过Xinference接入的OpenAI-API-compatible）
  • 点击「保存并嵌入」，等待处理完成

    • 3.3 RAG调优关键参数

    # 在Dify知识库「设置」中调试以下参数，找到你的数据的最佳配置：

分段策略：
  - 通用文档: 自动分段，800 tokens/chunk
  - 药品说明书: 按"【适应症】""【用法用量】"等标题分段（自定义分隔符）
  - 诊疗指南: 按章节标题分段

检索设置：
  - TopK: 3-5（医疗场景不要太大，减少无关信息干扰）
  - Score阈值: 0.6-0.75（过滤低相关度片段）
  - 重排序: 开启 Rerank 模型（bge-reranker-v2-m3）

# 医疗RAG的核心是"精准"而非"全面"，宁可少召回也不要召回错误内容

    4.2 第二个Agent：AI智能分诊转诊（4-8小时）

    # Dify →「创建应用」→「Workflow」

# Workflow节点设计：
[开始] → [LLM提取症状] → [条件分支]
  ├─ 急危重症（胸痛/呼吸困难/大出血/意识障碍）
  │    → [LLM: 生成紧急建议] → [标记: 立即急诊]
  ├─ 亚急性症状（发热1周+/疼痛持续/异常出血）
  │    → [知识库查询: 对应科室疾病] → [LLM: 生成转诊建议] → [标记: 建议转诊]
  └─ 轻症（感冒/轻微外伤/皮肤问题）
       → [知识库查询: 健康指导] → [LLM: 生成自护建议] → [标记: 基层处理]

# 变量设计：
- symptom_text (String) : 用户主诉
- severity (Enum)    : emergency / subacute / mild
- recommendation (String) : 最终建议
- target_department (String) : 推荐科室

    4.3 AI慢病主动管理引擎（8-16小时）

    # 核心Workflow结构：

[定时触发/API触发: 输入患者档案]
  → [条件分支: 疾病类型]

    第7章 常见问题与排错指南
    问题可能原因解决方法
    Dify容器启动失败 端口冲突（80/443被占用） 修改 .env 中 EXPOSE_NGINX_PORT 为其他端口
    Xinference模型回答极慢 虚拟机CPU/内存不足，模型太大或未量化 换更小的模型(qwen3:8b-Q4_K_M)；确认使用GGUF量化+llama.cpp后端；给VM加资源
    知识库检索不准确 分段策略不当 / TopK太大 减小chunk_size到500；降低TopK到3；开启Rerank
    Dify连接不上Xinference Docker网络隔离 把Xinference加入dify网络：docker network connect docker_default xinference
    虚拟机IP每次重启都变 Hyper-V Default Switch是NAT，IP不固定 给VM设置静态IP，或创建Hyper-V内部交换机
    Dify升级后数据丢失 docker compose down 默认不删volume 升级前备份：docker compose down && tar czf dify-data-backup.tar.gz ./volumes/
    模型医学知识准确性差 通用模型未经医学微调 使用MedicalGPT/HuaTuoGPT2等医学微调模型替代；加强RAG知识库
