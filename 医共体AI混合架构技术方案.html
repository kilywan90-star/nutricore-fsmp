2 内环 vs 外环：技术选型与分工
维度 内环：专业医疗AI（自研 / 采购专业厂商） 外环：Coze 智能体平台（低代码搭建）
核心定位 诊疗核心决策 —— 直接影响诊断、用药、医保结算的准确性和安全性 患者触达 + 管理提效 —— 健康咨询、随访、健教、文书、培训等"减负"场景
覆盖能力项 影像AI(#1)、CDSS(#3)、处方审核(#5)、医保审核(#6)、心电/超声(#7) 慢病管理(#4,10)、语音病历(#8)、随访(#11)、妇幼(#12)、心理(#14)、急救(#15)、分诊(#16)、数字分身(#19)、健教(#20)、培训(#18)、药品库存(#17)
技术栈 专用医疗模型（CNN/ViT/信号处理） + 医学知识图谱 + 规则引擎 + HL7/FHIR接口 Coze Agent + Workflow + 知识库(RAG) + 插件 + 语音/视觉API
数据要求 DICOM影像、HL7检验数据、结构化处方、医保结算单 —— 需要院内PACS/LIS/HIS实时对接 患者标签、健康档案摘要、随访记录、健康知识库 —— 可通过API批量同步，延迟和精度要求低
合规门槛 NMPA三类医疗器械认证（辅助诊断类）、数据不出院（本地化部署） 患者知情同意、数据脱敏、等保二级/三级。作为"辅助工具"可规避医疗器械认证
部署方式 院内/县域私有化部署 —— 数据安全底线要求 Coze云端SaaS + 数据脱敏网关。非敏感数据可上云，敏感数据通过API中转
开发周期 影像AI：12-18个月（含认证）；CDSS/处方：6-12个月（含知识库建设） 单个Agent：2-4周可上线MVP；全外环12项：4-6个月
年成本估算 影像AI约¥10-30万/病种/年；CDSS约¥15-25万/年；处方审核约¥8-15万/年 Coze企业版 ¥3-8万/年 + API Token ¥5-20万/年
迭代速度 慢 —— 模型更新需重新验证/认证，知识库更新需医学审核 快 —— Prompt/Workflow可视化调整，知识库实时更新，当天上线
灰色地带项 皮肤病/眼底筛查(#8) + 病案编码/DRG(#9) + 传染病预警(#13) —— 需要混合方案：Coze做前端交互和轻度推理，专业API做核心推断
3 数据流转路径（4条关键链路）

链路A：诊疗闭环

患者就诊全程

HIS挂号 → CDSS辅助问诊
→ 影像AI判读 → 处方AI审核
→ 医保AI审核 → 语音病历生成
→ 慢病随访计划

内环(诊断决策) + 外环(文书/随访)

链路B：慢病管理闭环

离院后的持续管理

出院 → AI慢病分层
→ 个性化管理计划
→ 语音随访 + 指标预警
→ 异常自动分诊
→ 复诊 → 方案调优

外环(Coze) + 内环(CDSS调方案)

链路C：公卫管理闭环

妇幼 + 传染病 + 心理

建档 → 高危自动分层
→ 节点智能提醒
→ AI健康宣教推送
→ 异常数据触发预警
→ 公卫数据自动上报

外环(Coze Agent)为主

链路D：患者自助闭环

居民自主健康管理

数字医生咨询
→ 轻症：健康指导
→ 中症：引导基层就诊
→ 重症：AI分诊转诊
→ 就诊后：随访+健教

外环(Coze Agent)为主

4 分阶段实施路线图

Phase 1 — 快速见效（0-6月）
外环优先，Coze低代码快速上线

  • 数字医生分身 — 2周MVP，先覆盖Top20常见问题
  • AI语音随访 — 1个月，对接公卫随访任务
  • AI个性化健教 — 2周，对接慢病患者标签
  • AI基层医生培训 — 1个月，3个常见病种模拟
  • AI药品库存优化 — 2周，数据驱动采购建议

此阶段全部用Coze搭建，零专业厂商依赖

Phase 2 — 核心能力（6-18月）
内环启动，专业厂商+自研

  • AI处方前置审核 — 采购/自研，药品知识库建设
  • AI辅助诊断CDSS — 对接EMR，本地化知识库
  • 影像AI辅助诊断 — 选择1-2家专业影像AI厂商
  • AI语音电子病历 — Coze+医学ASR（与Phase1衔接）
  • AI慢病主动管理 — Coze搭建管理引擎
  • 统一数据中台v1.0 — 患者主索引+基础API网关

Phase 3 — 生态闭环（18-36月）
内外环打通，数据驱动闭环

  • 医保AI智能审核 — 规则+ML，对接医保平台
  • AI心电/超声辅助 — 引入专业信号处理AI
  • AI多重共病管理 — Coze多指南RAG引擎
  • AI孕产妇/儿童保健 — Coze妇幼Agent
  • AI心理健康筛查 — Coze数字疗法Agent
  • 传染病AI预警 — 多源数据监测
  • AI院前急救指导 — Coze视频+急救知识库
  • AI病案编码/DRG — Coze+ICD知识库
  • 统一数据中台v2.0 — 全量数据打通
5 核心风险与缓解策略
风险 等级 具体表现 缓解措施
数据隐私合规 高 Coze云端SaaS vs 患者隐私数据不出院的法律要求 敏感数据经脱敏网关处理后再上传；内环全部本地部署；Coze仅接触匿名化数据；建立数据安全影响评估(DSIA)
模型幻觉 高 LLM生成不准确的医学建议或编码，导致临床风险或医保纠纷 关键场景(诊断/处方/医保)使用确定性规则引擎而非LLM；Coze场景设置置信度阈值+人工复核入口；所有输出标注"AI建议仅供参考"
医疗器械认证 高 CDSS、影像AI等辅助诊断功能可能需NMPA三类认证，周期长(1-2年)、成本高(50-200万) 初期定位为"医生参考工具"而非"辅助诊断系统"；优先选择已获证的影像AI厂商；法务前置评估每项功能的认证边界
系统对接复杂度 中 基层HIS/EMR厂商分散、接口标准不统一，对接成本可能远超AI本身 优先选择接口规范的HIS厂商合作；通过统一数据中台屏蔽异构系统差异；Phase1的外环场景降低对接要求
医生接受度 中 基层医生对AI缺乏信任、担心被替代、使用意愿低 从"减负"场景切入(语音病历)——先让医生感受到价值；聘请基层"种子医生"参与设计；AI定位为"助手"而非"替代"
Coze平台锁定 低 过度依赖Coze，未来迁移成本高 Agent逻辑以标准Workflow描述存档；知识库独立维护；预留Dify/LangGraph等开源替代方案接口
